# Chronicle

Задачи, привычки, ограниченные по времени челленджи, заметки и личный кабинет. Next.js App Router, React, NextAuth с Google и PostgreSQL через `pg`.

## Запуск

Нужны Node.js 22+ и PostgreSQL 14+. Используйте отдельную базу для разработки.

```sh
npm ci
cp .env.example .env.local
# Заполните DATABASE_URL, NEXTAUTH_URL, NEXTAUTH_SECRET и Google OAuth credentials.
npm run migrate
npm run dev
```

В PowerShell вместо `cp` можно использовать `Copy-Item .env.example .env.local`. Для Google задайте callback `http://localhost:3000/api/auth/callback/google` и соответствующий HTTPS callback для production. Секреты не входят в репозиторий.

```sh
npm run build
npm start
```

Без подключения базы приложение показывает ошибки, а приватные маршруты требуют действительную сессию. Демонстрационные данные и обход Google-входа в приложении отсутствуют.

## Что изменилось

- `/app/tasks`: задачи, время и даты, приоритеты, отдельные папки, поиск, фильтры, редактирование и удаление.
- `/app/calendar`: месяцы, выбор дня, настоящие задачи и их редактирование через общую модель задач.
- `/app/habits`: расписание по дням недели, история, исправление отметок, порядок и серии по запланированным дням.
- `/app/challenges`: шаблоны, создание, редактирование, архив, удаление и новые попытки. У попытки сохранён свой часовой пояс. 30 дней включают дату начала; результат 24/30 не считается полностью достигнутой целью.
- `/app/notes?folder=all&note=<id>`: папки, поиск, сортировка, закрепление, перемещение, корзина, восстановление и редактор с форматированием и чек-листами. На большом экране — три колонки, на телефоне — последовательные экраны в стиле Apple Notes.
- `/app/profile`: имя, аватары, настройки RU/EN, темы, времени и доступности, Telegram, экспорт, выход, завершение других сеансов и удаление аккаунта с повторным подтверждением личности.
- `/app/progress`: персонаж и ранги. XP вычисляется из сохранённых результатов: задачи 10/25/50, привычки 15, успешные дни челленджа 20. Отмена и удаление уменьшают XP; повтор запроса не увеличивает его.

`/app` направляет в задачи. Общий layout защищает все вложенные страницы. Настоящие маршруты и query-параметры сохраняют прямые ссылки и историю браузера. На телефоне дополнительные разделы доступны через меню «Ещё».

Страница достижений и интерфейсы веса/калорий удалены. Старые fitness/food API возвращают `410 FEATURE_RETIRED`, исторические таблицы не удаляются и остаются доступны в экспорте. Миграция не уничтожает прежние пользовательские данные.

## Архитектура и целостность данных

- `app/app`: страницы и защищённый серверный layout.
- `components`: общий интерфейс и отдельные компоненты разделов; `app/globals.css` содержит темы и стеклянные поверхности.
- `lib/api.js`: авторизация, проверка Origin, ограничения JSON, единые ошибки и приватные cache headers.
- `lib/tasks.js`, `lib/profile.js`, `lib/tracking-server.js`: прикладные операции с PostgreSQL.
- `lib/dates.js`, `lib/challenges.js`, `lib/habits.js`: правила календарных дат, серий и завершения.
- `lib/notes`: проверяемый формат Tiptap JSON и отдельная последовательная очередь сохранения для каждой заметки.
- `migrations`: версионированные SQL-миграции; транзакция, advisory lock и контроль checksum в runner.

Старые папки с задачами и заметками разделяются с сохранением связей. Текст заметок переносится в структурированный документ без выполнения HTML. Папки проверяются по владельцу и типу. Все изменения принимают владельца из сессии.

Заметки используют `version` и отвечают `409` при конфликте. Несинхронизированный текст сохраняется в локальном черновике, изолированном по аккаунту, заметке и вкладке. Пользователь явно выбирает версию при конфликте. Выход предупреждает об очистке черновиков. Подробности: [синхронизация заметок](docs/notes.md).

Next.js обновлён с 14.2.35 до исправленной ветки 15.5.24; редактор использует Tiptap 3.31.4. Обновления устраняют опубликованные уязвимости. React 18, PostgreSQL и NextAuth v4 сохранены. PostCSS зафиксирован на исправленной версии через npm override.

## Проверки

```sh
npm run lint
npm test
npm run test:db
npx playwright install chromium
npm run test:e2e
npm run build
npm audit
```

`test:db` поднимает собственный PostgreSQL на `127.0.0.1:55439`. Он проверяет пустую базу, старую схему с данными, повтор и конкурентный запуск миграций, checksum и полный откат при ошибке. Унаследованный `DATABASE_URL` не используется.

Playwright запускает `scripts/test-server.mjs`: собственный PostgreSQL на `127.0.0.1:55440` и Next.js на `127.0.0.1:3100`. Синтетические аккаунты находятся только в этой тестовой базе. В тесте создаются обычные NextAuth database sessions; production-авторизация не ослабляется. Базы сохраняются под игнорируемой Git папкой `.test-db` для диагностики, процессы завершаются вместе с harness. Убедитесь, что указанные порты свободны.

Если загрузка браузера недоступна, можно использовать установленный Chrome:

```powershell
$env:PLAYWRIGHT_CHANNEL='chrome'
npm run test:e2e
```

Проверки Google-сессий в локальном harness не заменяют реальный OAuth callback. Для приёмки на своём окружении необходимы действительные Google credentials, база и настройки внешнего Telegram-бота. Секретный webhook и успешное локальное сохранение не доказывают внешнюю доставку Telegram. Эмуляция 390 px не заменяет физический iPhone и его клавиатуру.

Проверка интерфейса проходит по всем семи разделам на ширинах 390, 768 и 1440 px в светлой и тёмной темах. Снимки пустых экранов из изолированной тестовой базы: [телефон](docs/screenshots/challenges-390-dark.png), [планшет](docs/screenshots/notes-768-light.png), [компьютер](docs/screenshots/tasks-1440-light.png). Тест проверяет отсутствие горизонтальной прокрутки и ошибок JavaScript.

## Развёртывание и Telegram

Следуйте [руководству развёртывания](DEPLOY_GUIDE.md). Перед обновлением сделайте резервную копию PostgreSQL, примените `npm run migrate`, затем запустите новую сборку. Не запускайте автоматические тесты на production-базе.

Поддерживаемый контракт внешнего бота, одноразовая привязка, секреты webhook/cron и ограничения доставки описаны в [backend-документации](docs/BACKEND.md). Код внешнего бота в этом репозитории отсутствует.
